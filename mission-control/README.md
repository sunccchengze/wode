# 指挥舱 · MISSION CONTROL

> 把 `sunccchengze/zixue2026` 里**手写的**多学科 Markdown 台账，收成一个能刷卡、能对账、能写回的指挥舱。
> 编号 NO 001 · 数据基准日 2026-09-14 · 三套测试 84 项全绿

---

## 一、这是什么

你在 `zixue2026` 里手写维护了一整套多学科科研式学习系统：总调度表、每学科的
`memory/` 骨架、`drill-ledger` 间隔重复账本、大师天团、判例库、路线图。
它很扎实，但它是**纸面**的——想知道"今天到底该刷哪些卡"，得翻 9 个目录、
45 个账本文件，自己心算 due 日期。

指挥舱做的事：**把这些纸面台账收成一个可运行的东西。**

| 视图 | 干什么 |
|---|---|
| **总览 BRIDGE** | 9 个学科舱段，各自的卡数/到期数/最长逾期/路线图进度/交付物，状态 emoji 直接取自你的总调度表 |
| **今日作战 OPS** | 真能刷的卡。到期优先、逾期越久越靠前、同课题不连刷超过 2 张；`1`–`4` 键盘评分 |
| **学习地图 MAP** | 各学科路线图课题铺成流水线，绿=已开卡、黄=当前攻关 |
| **大师天团 COUNCIL** | 26 位大师（28 份文件按人去重）列出，点开看心智模型与**局限**（连同你原文的诚实声明） |
| **台账核对 LEDGER** | index.md 声称卡数 vs 明细实数的对账表 + 空账本告警 + 刷卡回写预览 |
| **我的偏好 ME** | 36 条硬偏好 + 63 条判例，每条都带 `文件:行号` 溯源 |

刷卡用的是 **FSRS-4.5**，因为你的账本存的正是它的两个状态量（`S` 稳定性 / `D` 难度）。
刷完的 S / D / due 能按你原来的表格口径导出成 Markdown，直接贴回台账文件。

## 二、跑起来

```bash
# 起服务（模块加载需要 http，不能直接双击 index.html）
cd mission-control
python3 -m http.server 8770 --bind 0.0.0.0
# → http://localhost:8770
```

**同步台账**按钮会从 GitHub 公开 API 拉 `zixue2026` 最新的账本重新解析（未登录限流 60 次/小时）。
拉不到就继续用 `data/snapshot.json` 这份离线快照，不会假装成功。

**离线重收割**（快照过期时）：

```bash
git clone https://github.com/sunccchengze/zixue2026 /tmp/zixue2026
python3 tools/harvest.py --repo /tmp/zixue2026 --today 2026-09-14
```

## 四、解析过程中踩到并修掉的四个真坑

这四个都是**真数据**里的问题，不是假想边界。每个都留了回归测试。

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| 1 | 东方智慧把整行表格写在反引号里当行内代码 | 4 张卡直接漏收 | 剥掉行首尾反引号再判表格行 |
| 2 | 概念里有**转义**竖线 `P(B\|A)` | 5 张卡被切碎、整列右移 | 只按「前面不是反斜杠」的竖线切 |
| 3 | 概念或历史里有**未转义**裸竖线（`E\|X\|`、`\|z\|>1`、原电池符号 `Cu\|Cu²⁺`） | 4 张卡 S/due 全丢 | 用「S数字·D数字·last日期·due日期」四连做锚点重切列，两侧各自拼回 |
| 4 | 总调度表一门课挂多个文件夹（`probability/`+`概率论与数理统计/`） | 学科被拆成 11 个、概率论和复变各出现两次 | 按学科名合并，主文件夹取"真有台账的那个" |

第 3 条的第一版修法是错的：我先假设"只有概念列会出现竖线"，结果把复变课题01
第 6 张卡的 S/D 一起吃进了 concept（`s` 解析成 `2026.0`）。改成右侧锚点定位才对。
**修过的每一张卡都进 `parse_warnings` 留痕，不静默改数据。**

## 五、验证

```bash
ZIXUE_REPO=/path/to/zixue2026 ./check.sh
```

三套测试，共 **84 项**（`26 + 20 + 10 + 28`）：

| 套件 | 数量 | 测什么 |
|---|---|---|
| `tests/test_harvest.py` | 26 | 收割器：转义竖线、两种表头写法、复合卡号、空账本、溯源行号、对账假警报 |
| `tests/test_scheduler.mjs` | 20 | FSRS：遗忘曲线单调性、`t=9S→R=0.5`、打脸后 S 必降、leech 4 次、纯函数不改入参 |
| `tests/test_ledger_parity.mjs` | 10 | **两份解析器交叉验证**：Python 与 JS 对同一批文件必须逐卡一致 |
| `tests/dom_smoke.mjs` | 28 | jsdom 载入**真实** `index.html` + `app.js`，断言渲染出的是真数字、刷卡真改状态 |

`test_ledger_parity.mjs` 是这里的关键：`js/ledger.js`（浏览器端同步）和
`tools/harvest.py`（离线收割）是同一套口径的两份实现，**任何一方跑偏这里就红**。
它已经抓到过 5 个真分歧——逾期天数符号反了、判例重复计数、以及 `cells` 写成
`const` 导致需要重切的行直接抛异常。

DOM 冒烟测试跑的不是替身逻辑，是浏览器里那份 `app.js` 本身：
它会断言 hero 上的 `296` 等于快照里的 `cards_due`、45 个舱段进度环都在、
按 `Good` 之后 S 真的上升、`Again` 真的挂上 `cw` 标记、
以及在总览视图按数字键**不会**误刷卡。

## 七、边界（说清楚它不做什么）

- **不改你的台账。** 只读 + 报差异 + 导出可贴回的 Markdown。要不要写回，你决定。
- **不猜。** 解析不出来就进 `parse_warnings`，不用默认值填空。
- **FSRS 用默认权重**，没按你的历史复习数据拟合——298 张卡里绝大多数从没在软件里刷过，
  拟合不出可信的个人参数。等你在指挥舱里刷上几百次，再谈个性化权重。
- **判例库/偏好的正文**是从 Markdown 逐条抽的，长条目会被压成一行；溯源到 `文件:行号`，
  想看全文点回仓库。
- **实时同步依赖 GitHub 未登录限流**（60 次/小时）。台账文件约 60–80 个，
  一次同步会吃掉大部分配额；失败时如实报错并回退到快照。
